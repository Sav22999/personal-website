# FoodTrack

Multilingual web app (Italian and English), installable as an Android app, for domestic food management: spaces (fridge,
freezer, pantry…), products with expiry dates, upcoming and expired product alerts with helpful advice, shopping lists,
recipes with available ingredient calculations, weekly meal planner, and **shared households** between multiple users.
Includes an **administration portal** for recipes, product catalogue, categories, and users.

Originally created as a Mobile Application Design project (University of Udine) — Flutter prototype — and rewritten as a
web app with a PHP/MySQL backend.

Online: `https://www.saveriomorelli.com/projects/foodtrack/`

## Server Installation (Aruba)

1. Upload the `projects/foodtrack/` folder via FTP (`android/` is not required on the server, but is blocked if uploaded).
2. Open **`https://www.saveriomorelli.com/projects/foodtrack/install-db.php`** and enter:
    - host (`$localhost_db`), user (`$username_db`), password (`$password_db`), and database name (`$database_name`) from the hosting control panel;
    - table prefix (default `ft_`);
    - name, email, and password for the **master admin**.
3. The installer creates tables, loads 13 categories, 500 products, and 206 recipes (in Italian and English, across 35+ countries), creates the master admin (with their household), and writes `credentials.php`. If PHP cannot write the file, manual instructions are displayed.
4. **Delete `install-db.php` from the server** (re-upload only when migrating schema: in that case it prompts for the database password).
5. Ensure PHP has write permissions on `uploads/recipes/` (`755`) to allow uploading recipe images from the portal.

### Alternative: phpMyAdmin

Import `install/foodtrack.sql` (under the "Import" tab, once, on an empty database), copy `credentials-sample.php` to `credentials.php`, and complete credentials. Then register via the app and elevate your account to master admin:

```sql
UPDATE ft_users SET role = 10 WHERE email = 'your@email.com';
```

After editing `lib/schema.php` or `lib/seed.php`, regenerate the SQL file with `php tools/build-sql.php`.

## Product Storage Environments

Every catalogue product specifies a storage environment: **frozen** (freezer), **cool** (fridge), **room temperature**, or **warm**. Configured via the admin portal; default catalogue entries are pre-classified in `seed_product_environment()` (`lib/seed.php`). Each space has an identical field, suggested by icon and editable in the space settings. In shopping lists, individual product environments can be tweaked, which is especially useful for custom uncatalogued items.

Moving an item from a list to a space suggests the first space matching its environment, both for individual items and via "Move all to their spaces". If an environment is unset or no matching space exists, the user is prompted. On existing databases, schema migration 12 populates environments based on space icons (freezer, fridge, cooler bag; others default to room temperature).

## Member Activity Notifications

In shared households, members are notified about activity from others: products, spaces, lists, meal plans, joins, and leaves (`NOTIFIED_ACTIONS` in `lib/push.php`). Notification categories can be configured in Profile → "Notifications" (persisted across devices via `users.notify_off`).

- **App foreground:** polled every 30 seconds, displays toast message.
- **Browser, app background/closed:** Web Push. The server dispatches a content-free wake-up ping (VAPID key pair generated on first use and stored in `meta`); the service worker fetches notifications securely from `activity.pending` using the authenticated session. Push gateways never receive household data. On iOS, requires adding the PWA to the Home Screen.
- **Android App, closed:** WebViews do not support Web Push directly; `ActivityJobService` polls `activity.pending` approximately every 15 minutes (subject to OS battery optimisation).

## Measurement Units

Preferred units for weights (g, kg) and volumes (ml, cl, dl, l) can be chosen in user settings: "As entered", "Automatic", or a fixed unit. This is purely a display conversion (`preferredQty` in `assets/ui.js`) stored locally: the database retains raw entered values, and edit forms display original inputs.

## Custom Dropdowns

On mouse-driven devices, `<select>` elements in the app and portal open custom styled flyouts ("Dropdowns" section in `assets/ui.js`) rather than operating system pickers: unified aesthetic across platforms, emoji flags and icon support (`flag` and `pic` options), live filtering for lists with 10+ entries, full keyboard navigation. The underlying `<select>` remains present and bound to state. On touch screens, native pickers remain active for convenience.

## Recipe Editor (Portal)

Ingredients are selected from a searchable grid catalogue (supports English and Italian titles), category filters, and most frequently used items: full-screen on mobile, opens at current selection, and facilitates rapid successive additions. Missing items can be created directly without abandoning the recipe form. The `INGREDIENT_EDITOR` constant in `assets/admin.js` toggles between `'v2'` (card catalogue) and `'v1'` (dropdown table). Unlinked legacy recipe text is preserved with warnings on save. Steps can be reordered with arrow buttons or drag-and-drop: Italian and English steps stay synchronised, and missing translations fall back to Italian.

## Household History

The timeline logs all household mutations: products, spaces, lists, meal plans, members, and household settings. Actions modifying products within spaces can be reverted (`UNDOABLE_ACTIONS` in `lib/bootstrap.php`). Favourites do not appear on the household log because they are strictly personal. Entries load in batches of 100 via "Load more".

## Recipe Portions

In recipe view, − and + buttons adjust portions (range 1–50) and recalculate ingredient quantities automatically, rounded sensibly for the given unit; "to taste" and unmeasured ingredients remain unchanged. Available and missing ingredient counts update in real time. Default portion settings in user profile govern initial recipe presentation, catalogue listing counts, and shopping list exports from the weekly meal planner. Stored locally per device.

## Sign in with Google (Optional)

The app and admin portal render official "Continue with Google" buttons when `$google_client_id` is set in `credentials.php`. No client secret is required: the server verifies Google tokens directly, checking audience against your Client ID and validating email verification.

1. Navigate to [Google Cloud Console](https://console.cloud.google.com/) and create a project (e.g. "FoodTrack").
2. Note: Google Sign-In requires **only one "Web application" client**, even for the Android app (which loads through Chrome/TWA, presenting origin `https://www.saveriomorelli.com`). A native Android OAuth client is not required for TWA mode.
3. **Google Auth Platform → Branding** (OAuth consent screen): External, App name "FoodTrack", support email, logo (`android/play-store-icon-512.png`), authorized domain `saveriomorelli.com`, privacy policy link `https://www.saveriomorelli.com/projects/foodtrack/privacy.html`. Scopes: `openid`, `email`, `profile` only (non-sensitive scopes require no verification). Publish app to Production.
4. **Google Auth Platform → Clients → Create client**: Type **Web application**, Name "FoodTrack Web".
    - *Authorized JavaScript origins*: `https://www.saveriomorelli.com` (and `https://saveriomorelli.com` if served naked).
    - *Authorized redirect URIs*: none needed (popup auth flow).
5. Copy the **Client ID** (ending in `.apps.googleusercontent.com`) into `credentials.php`:
   ```php
   $google_client_id = "1234567890-xxxx.apps.googleusercontent.com";
   ```
   or enter it via `install-db.php` (including update mode).
6. Done: first-time Google sign-ins accept privacy terms; existing accounts with matching emails link automatically. Google accounts can be linked or unlinked in Profile.

In the Android app (TWA), Google Sign-In runs in Chrome. In rare fallback environments without Chrome where WebView is invoked, Google blocks web login: standard email and password login remains available.

## Tutorial

Upon first login on a device (and after major version increments in `VERSION` in `assets/app.js`), an illustrated tutorial introduces: spaces, products, expiry alerts, shopping lists, recipes, and shared households. Replayable at any time from Profile → Preferences → "App tutorial". Language can be selected inside the tutorial; illustrations support animations (respecting reduced motion settings).

## Emails

FoodTrack dispatches two transactional emails upon account registration (email/password, Google, or portal):

- To the user: localized welcome message with app link;
- To the master admin: registration alert with name, email, and registration method (can be disabled via `$mail_notify_admin = false;` in `credentials.php`; not triggered for accounts manually created in the admin portal).

SMTP configuration: uses `$mail_config` in `credentials.php` if defined (see `credentials-sample.php`), falling back to website contact form settings (`/.mail-config.php`). Without configuration, emails are silently skipped without disrupting registration. Dispatches occur asynchronously post-response so sign-ups remain instant.

## Desktop Version

At widths 960px and wider (desktop and landscape tablets), the UI transitions into a full desktop workstation layout: collapsible navigation sidebar (active household, expiry and shopping badges, user profile), top primary actions, grid views, two-column recipe views, week view grid, centered modal dialogs replacing bottom sheets, contextual popover menus, and two-column auth layouts. Shortcuts: `/` to focus search, `Esc` to close modals. Administrators and Content Moderators see a quick launcher to the "Admin Portal" in the sidebar. The admin portal shares identical desktop components and responsive mobile design.

## Languages

- App and portal interface is available in **Italian** and **English**: language defaults to browser locale and can be switched in Profile (or portal sidebar). Source strings are in English; translations are centralized in `assets/i18n.js` (frontend) and `lib/i18n.php` (API responses).
- **Content** is fully translatable: categories, product catalogue, recipes (name, description, cooking notes, steps), and ingredient notes. The primary content language is Italian; the portal editor provides dual tabs "Italian · primary" / "English". Missing translations fall back cleanly to Italian.
- **Per-language publication status** for recipes: each locale tracks *Published*, *Draft*, or *Untranslated*. The app only lists recipes published in the user's selected language; the portal displays status badges (green, yellow, struck-through).
- Custom user-added products retain original catalogue names in the user's locale until explicitly renamed.

## Barcode Scanning

Barcode scanning uses the native browser `BarcodeDetector` when available (Chrome on Android) and falls back to bundled **ZXing** (`assets/vendor/`), enabling support in Firefox, Safari, and desktop Chrome. Requires HTTPS and camera permissions (configured in `.htaccess`: `Permissions-Policy: camera=(self)`). Barcode lookups query Open Food Facts via the backend.

## Seed Recipes

206 curated recipes with concise instructions in Italian and English, originating from Italy, England, Scotland, Wales, Ireland, United States, Canada, Mexico, Peru, Brazil, Germany, Austria, Switzerland, France, Belgium, Netherlands, Sweden, Poland, Hungary, Greece, Spain, Portugal, Turkey, Lebanon, Egypt, Morocco, Tunisia, China, Japan, South Korea, Thailand, Vietnam, and India (`lib/seed.php`, `lib/seed-recipes-2.php` through `6.php`). Seed recipes are inserted once on first run; deleted recipes do not respawn. **All 206 seed recipes include cover photos** (`assets/img/recipes/`, mapped in `lib/seed-images.php`): batches 2 through 7 are **Public Domain or CC0** (Wikimedia Commons), cropped to 1200×800; sources credited in `assets/img/recipes/CREDITS.md`. Missing photos show illustrated country flag graphics.

## Shared Households

Each user has at least one household (created on registration with default Fridge, Freezer, and Pantry). Spaces, products, shopping lists, and meal plans belong to the household and are shared across all its members.

- Invite: Profile → "Invite someone" shares an 8-character code or link `…/#/join/CODE` (legacy `#/unisciti/…` links remain supported).
- The household owner can rename the household, regenerate codes, remove members, transfer ownership, or delete the household.
- Users can belong to multiple households (e.g. primary home, vacation house) and toggle between them from the header chip.
- Polling synchronises state every 30 seconds and on window focus.

## Android App (Google Play)

The `android/` directory is an **Android Studio** project (Java) wrapping the web app in a **full-screen native WebView**. Behaves consistently across Android devices regardless of default browser. Web updates deploy immediately to the app without requiring new Play Store releases.

Native integration (`MainActivity.java`, exposed as `window.FoodTrackAndroid`):

- **"Continue with Google"** with Credential Manager: fetches Google ID tokens natively and transfers them to the web page for backend verification;
- **Notifications** for expiring food products (permission requested via Profile toggle);
- **Camera** for barcode scanning (permission requested on first scan);
- File picker (image uploads in admin portal), hardware back button handling, invite links deep linking, external links opening in external browser, offline fallback screen, system light/dark theme tracking.

Steps:

1. Open `android/` in Android Studio (File → Open) and wait for Gradle sync.
2. **Package name**: `com.saverio.foodtrack` (in `app/build.gradle.kts`): cannot be changed post-publication.
3. Signing key: Build → Generate Signed App Bundle / APK → Android App Bundle → Create new… Store `.jks` outside repo. Or copy `keystore.properties.sample` to `keystore.properties` (gitignored).
4. **Google Sign-In in Android app**: in Google Cloud Console, under the **same project** as the Web application client, create an **Android** OAuth client ID with package `com.saverio.foodtrack` and the **SHA-1** fingerprint for each key (debug key and Google Play App Signing key). The backend continues verifying the token against `$google_client_id`.
5. Upload `.aab` (`app/release/app-release.aab`) to Google Play Console. Store icon: `android/play-store-icon-512.png`; privacy policy: `https://www.saveriomorelli.com/projects/foodtrack/privacy.html`. Store listing copy, screenshots (1080×1920), and feature graphic (1024×500) are in `android/store/` (`listing.md`).
6. **Digital Asset Links** (recommended for deep links): add to `/.well-known/assetlinks.json` with the **SHA-256** fingerprints of your keys.
7. Bump `versionCode` and `versionName` on Android updates.

## Security

- Passwords hashed with `password_hash`, sessions tracked via random tokens in HttpOnly/Secure/SameSite cookies (SHA-256 hash in DB), CSRF protection on mutations, strict JSON API endpoints.
- Rate limits on login, registration, and invitation codes.
- All operations validated server-side against the user's active household; admin actions enforce role hierarchies.
- `credentials.php`, `lib/`, `install/`, `tools/`, and `android/` are blocked from web access; `uploads/` disables script execution and re-encodes uploaded images.
